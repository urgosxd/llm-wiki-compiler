# CLI removal

The `llmwiki` executable leaves the product: `packages/wiki/src/cli.ts`, `packages/wiki/src/cli/**`, the 32 CLI-only `packages/wiki/src/commands/**`, the `compiler-cli` barrel, and the six capabilities that only the CLI reached. A new `@repo/api` launcher replaces it as the container entry. Branch `chore-remove-cli`, base `bb7d842587df101f424f77ddb04b130dc489c15f`.

## Specs

**S1 — The CLI leaves the product.** User's decision, verbatim: `b se va del producto, spawnea y hace lentos los tests, eliminalo`. This is a breaking product change, executed deliberately rather than by grep. Every requirement here traces to that sentence and to the constraints it was authorized under; none exists because a census suggested it.

**S2 — Six capabilities leave with it.** User's decision on the capability losses, verbatim: `salen esas capacidades`. The six are the stranded data-path capabilities, each reachable only from a deleted command: `rm` (delete a source with its derived pages, links and state rows — `sources/removal.ts:188` `planRemoval`, `:287` `applyRemovalLocked`, `:418` `regenerateDerivedLocked`, plus `wiki/delete-page.ts`); `visualize` (`viewer/navigation-write.ts` `writeDerivedArtifact`); `lint --fix-preview/--fix-propose` (`linter/fix-plan.ts` `planLintFixes`); `ingest-session` (`adapters/registry.ts`); `eval cache clear` (`eval/cache.ts`); `review reject` (`compiler/candidate-rejection.ts`). Each deletion must be verified against `git grep` before it happens — the census that produced this list cited at least one path that does not exist.

**S3 — The container is never left without a launcher, not even for one commit.** `Dockerfile:137` is `ENTRYPOINT ["/usr/local/bin/entry.sh"]`. `docker/entry.sh:64` and `:66` run `node /app/dist/cli.js host --port …` (with `--host … --allow-lan` in the LAN branch) and `:84` runs `exec node /app/dist/cli.js serve`. There is no non-CLI executable in `dist/`. Therefore the new `@repo/api` entry and the `entry.sh` re-point land in the same commit as the CLI deletion. `Dockerfile:39-44` copies only the `llmwiki-core`, `llmwiki-kg/ts` and `wiki` manifests before `RUN pnpm install --frozen-lockfile` (`:45`); because `packages/api` is a root workspace (`package.json:8`) whose manifest is never copied, adding `@repo/api` as the entry requires that COPY block to carry `packages/api/package.json` or the frozen install fails.

**S4 — `deleteSource` leaves too.** It is the SDK's half-capability: it `unlink`s the raw source and leaves derived pages, links and state rows behind (`packages/wiki/src/sdk/core.ts:130` → `packages/wiki/src/sources/store.ts:51-61`). Removing `rm` while keeping it converts "no delete" into "delete, but it corrupts". Find every caller, remove it, and report the blast radius.

**S5 — Port before deleting.** The ~43 cases whose behaviour has no in-process counterpart must be ported to the shared modules they compose, not to the command files, which are deleted: `next-integration` (11 cases), `rules-integration` (6), `quickstart-integration` (19), `cli/stack-option*` (5), `bridge-export-contract-cli:88,:104` (2 — a `projectId` traversal/oversize **security boundary**). The targets are `project/recommendations.ts`, `commands/ingest.ts` + `compiler/index.ts`, and `sdk/*`.

**S6 — Do not delete.** The 23 non-CLI spawners (`npm pack` guards, `git`/`sh`/`ps`/`mkfifo`/`tsx`/`vitest`); `test/test-partition.test.ts` (it spawns nothing, it tests the classifier); `test/parity-default.test.ts`'s MCP + viewer captures; and the 14+ MCP stdio tests. The MCP tests spawn `node dist/cli.js serve` but they are the only coverage of the MCP surface, which survives — re-point them at the new MCP entry.

**S7 — The artifact pin goes to 0.** `test/artifact/dist-specifiers.test.ts`'s total-count pin is 2, and its own comment says the count exists because `commands/host.ts` inlines `packages/wiki/package.json`. When that file goes, the pin goes to 0 and the comment is corrected.

**S8 — The partition blind spot is handled explicitly.** `test/fixtures/run-cli-server.ts` and `test/fixtures/mcp-test-env.ts` spawn the CLI, so 13 files classify as `unit` while spawning — including `test/viewer-server.test.ts`, the third slowest file in the suite. These fixtures must be re-pointed or removed; they must not become dead files that keep a deleted binary in the graph.

**S9 — What goes, what replaces it, and which surfaces name it.** Delete `packages/wiki/src/cli.ts`, `cli/**`, `compiler-cli.ts`, the 32 CLI-only `commands/**`, and the stranded implementations from S2. Create the `@repo/api` entry that `docker/entry.sh` runs — `host` and `serve` with the flags the script passes today; `@repo/api` is the only package allowed to join wiki and kg, so the composition root belongs there. Retire these surfaces or every run reports a stale build: `package.json`'s `bin`, the `cli` tsup entry and its shebang banner, the `files`/`exports` entries naming it, `.fallowrc.json`'s two entries (`:6` `cli.ts`, `:8` `compiler-cli.ts`), `scripts/build-stamp.ts:63`'s `REQUIRED_OUTPUTS` entry, `scripts/demo.sh`, `scripts/dev-viewer.mjs:104`, and the `dev:view` script.

**S10 — Docs ship in the same slice as the removal.** The 20 CLI reference pages (`docs/docs.json:46-74`) and the 7 `npm install -g` instructions. Shipping docs for commands that no longer exist is worse than shipping none. The ~634 inline `llmwiki <cmd>` prose occurrences in 57 files may follow as a separate batch if this slice is already large, and the report must say which was done and which deferred.

**S11 — CHANGELOG.** Record the removal and the `bin` retirement as a breaking change: consumers who ran `llmwiki <command>` lose it entirely; the library surface (`createWiki`) is unchanged.

**S12 — Acceptance.** (1) The image starts from the new entry in both modes (`host` and `serve`), proven by executing it — not by a green build; that includes a real `serve` start, since the stdio MCP path is reachable from no other entry. (2) `wiki → @repo/api` stays 0 in production zones, and `@repo/api` imports both wiki and kg. (3) The suite is measurably faster, with before/after wall time reported at `maxWorkers: 4`; the measured expectation for deleting all 75 CLI-spawning files was 137 s of 533 s (25.7%), and a materially different number must be explained rather than restated. (4) No test that spawns a non-CLI target was deleted. (5) Renames, not copies.

**S13 — Gates.** `gates:static`, `tsc --noEmit`, `typecheck:tests`, `typecheck:kg`, `lint` (643/466/496 ceiling, literal triple), `build`, `fallow:ci`, `fallow:kg`, `test/artifact/*`, artifact proof in its new form, `pnpm test` in full and alone, and `test:pack`.

**S14 — Prohibitions.** No history rewriting (no `git reset`; a fixup commit is disclosed instead), no push, no `--no-verify`, no `HUSKY=0`, no `cp -a` of this worktree, no deleting the MCP stdio tests, no deleting a non-CLI spawner. `odd/tasks/**` is append-only except the tracker line.
