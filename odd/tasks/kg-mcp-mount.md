# kg-mcp-mount

Make the four KG MCP tools reachable, authenticated, from the **shipped** `packages/llmwiki-kg` image. One process, one port: `/mcp` mounted on the existing Express app. `createApp` and the Dockerfile `CMD` stay untouched.
Branch `fix/kg-mcp-mount`. Route: `gentle-ai-worker` for writes, `gentle-ai-verify` for independent verification.

## Specs

**S1 — acceptance criterion (corrected by the Manager; "enumeration plus one working call, or it is not done").**
From the image built by `packages/llmwiki-kg/Dockerfile` **with no entrypoint override**, a client can enumerate **exactly four** tools — `query_stack`, `traverse_stack`, `get_entities`, `list_stacks` — **and** issue one real `tools/call` on `list_stacks` that succeeds end to end. The earlier criterion, verbatim: *"a client can enumerate exactly four tools"* — **rejected, because "a stdio CMD satisfies that literally while every `tools/call` hits `http://localhost:8000` where nothing listens"**. `list_stacks` is the chosen call because, verbatim: *"it hits `/stacks`, reads the graph, calls no provider, and therefore needs no spend."*

**S2 — shape.** Verbatim: *"Mount `/mcp` on the existing app. Reject the stdio CMD"* … *"One process, mirroring `packages/api/src/host/mcp-http.ts` stateless (`sessionIdGenerator: undefined`, self-parsed body, `server.close()` in `finally`). `createApp` untouched — you are right that `packages/api` composes it and mounting there would change a shared surface. No Dockerfile change, which is the strongest argument for this shape: the CMD is already correct."*

**S3 — auth, a deliberate divergence that must be documented.** Verbatim: *"Auth: `requireApiKey`, and I want it stated as deviating deliberately."* … *"The wiki `/mcp` being unauthenticated is not a model — it is a defect, and copying it would spread it. Every other KG route is protected; `/health` alone is public. An unauthenticated `/mcp` on KG exposes `get_entities` and `traverse_stack` — graph reads over the whole stack — to anyone who reaches the port. Parity with wiki here would be a security regression dressed as consistency."* … *"So: `requireApiKey`, and say in the commit message and the record that the divergence is intentional, with that reason. A deliberate divergence documented is worth more than a silent parity."*

**S4 — the guard must be tested.** Verbatim: *"add one test that fails if the guard is removed — a request without the key must be refused with the same shape the other routes use. A guard nobody tests is a guard the next refactor deletes."*

**S5 — tool contracts unchanged.** Same four names, same schemas, same output shape. `list_stacks` is a shared name with the wiki's server; it counts once here, and the wiki's 13 tools belong to a different process.

**S6 — existing HTTP API preserved.** `/stacks`, `/aks/v1`, ingest and synthesize must keep working. `packages/wiki` must not be touched.

**S7 — negative control.** A request to a path that is not mounted must return a body distinguishable from the mounted-but-resource-missing case. Established earlier: `{"detail":"Not Found"}` (route mounted, resource missing) and `{"error":{"code":"not_found"}}` (router never ran) are different outcomes.

**S8 — deployment delta, recorded and NOT fixed.** Verbatim: *"`validateConfig` runs before `listen` and only checks presence, so three provider-free tools inherit a boot gate. Making it lazy changes semantics the suite pins — not zero-cost, so it stays as an observation."*

**S9 — the wiki-side shape must be recorded correctly.** Verbatim: *"The wiki does not run one process on both transports — stdio is a separate subcommand (`main.ts:119`), and HTTP is `host/mcp-http.ts`. I asserted a shape that does not exist, again. State the real shape in the file, so the next person does not repeat my assumption."*
