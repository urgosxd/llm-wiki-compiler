# fallow-root-gate — make `npm run fallow:ci` threshold-aware, so a clean tree exits 0

Branch `fix/fallow-root-gate`. The repo-wide fallow gate counts raw clone groups,
so it fails on `main` with no changes at all; this delivery re-points the root
invocation at `fallow audit --gate new-only` without weakening CI.

## Specs

- S1 — Defect, measured: `scripts/check-fallow-report.mjs:17` counts `report.dupes.stats.clone_groups` into a sum at `:23` and fails at `:26` on `total > 0`. On a clean `main` with no changes at all, `dupes.stats.clone_groups` is 20 and every one of those clone groups is below fallow's own duplication threshold (`fallow` itself exits 0 on the same tree). Consequence, proven: `npm run fallow:ci` exits 1 on `main` today, so the `AGENTS.md` pre-commit gate 5 is unsatisfiable on any branch, while CI's `fall-on-issues` uses threshold semantics and stays green. Local and CI disagree, and the local one can never pass.
- S2 — Chosen cure: "re-point the root invocation at `fallow audit --gate new-only`, the form the KG gate uses, so 'new' means 'absent from a baseline' locally as well." Rejected alternate (a): "read fallow's threshold semantics rather than raw counts — if the JSON exposes a 'above threshold' figure, count that" — rejected because 2.82.0 exposes no such figure and `--threshold` is inert, so implementing (a) would require inventing a threshold in the script.
- S3 — "On a clean tree with no changes, `npm run fallow:ci` exits 0. This is the bug; it must be demonstrably fixed."
- S4 — "It still bites. Introduce one genuine new issue (an unused export in `src/`), run, require exit 1 naming only that finding, then remove the probe and show `git status --short` empty."
- S5 — "CI is not weakened." `.github/workflows/ci.yml` keeps `fail-on-issues: true`; no `continue-on-error`; no lowered thresholds; the 13-line `auto-changed-since` comment above `codebase-health` stays byte-identical; no job key renamed.
- S6 — "Test-first": RED first in `test/ci/fallow-report-gate.test.ts`, with a case proving 20 below-threshold clone groups must NOT fail, and a case proving a real above-threshold duplication regression DOES fail.
- S7 — "Document what 'new' means" in `docs/fallow-gates.md`, in one paragraph a reader can act on.
- S8 — Out of scope, named and NOT fixed: `scripts/check-fallow-report.mjs:18` reading the baseline-blind `functions_above_threshold`; its ignoring of `coverage_unavailable`/`unknown` verdicts; the unbuilt-`dist/` findings that make a full-tree run red without `npm run build`; `.husky/pre-commit` gating nothing.
