---
title: "Lifecycle Profiles Are Fixed"
sidebarTitle: "Profiles"
description: "llmwiki ships one fixed profile: concepts in wiki/concepts and saved query answers in wiki/queries. No profile file is read and nothing is declarable per project."
---

llmwiki has one profile, and it is fixed. A run compiles sources into concept pages under `wiki/concepts/` and writes saved query answers to `wiki/queries/`. Those two directories are the whole shape of a wiki.

Nothing about that shape is declarable. No profile document is read: `.llmwiki/profile.json` has no reader. There are no built-in or local profile templates, and no lifecycle, workflow, artifact, or connector declarations exist to install. A project selects nothing, so two projects given the same sources compile the same way.

The profile a project has is something you can observe rather than configure. `loadNonDefaultProfile()` returns `undefined` for every project, because every project is the built-in default, and `activeProfileDigest()` returns the content-address of that single profile so a host can record which configuration it verified against.

If you are looking for how to configure a project, the answer is the Stack it addresses - connection and tenancy come from the Stack, not from a profile document.
