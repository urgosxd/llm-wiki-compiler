Open Knowledge Format (OKF) is a markdown-bundle shape for sharing compiled knowledge between tools. llmwiki can act as both a producer and a consumer:

- `wiki.exportOkf()` writes a portable OKF bundle from your compiled wiki, and the MCP tool `export_okf` does the same over the wire.
- `wiki.importOkf(dir, { trusted: true })` reads an OKF bundle and writes its documents into the wiki; an import that does not name `trusted: true` refuses instead of staging, because no surface promotes a staged candidate.
- Re-export preserves foreign producer keys, raw foreign types, and safe original bundle paths while refreshing llmwiki's own metadata.
- A bundle written by an earlier version may carry a bundle-level `x-llmwiki` block with profile identity and relation entries; the importer still parses it, and this build does not write one.
- SDK and MCP callers can export/import OKF without shelling out.

Use OKF when you want to exchange compiled knowledge with another tool or project. Use JSON export when you are feeding a programmatic importer that expects llmwiki's JSON bridge contract.

## Export a bundle

```ts
await wiki.compile();
const bundle = await wiki.exportOkf({ out: "./dist/knowledge-bundle" });
```

The bundle contains:

```text
knowledge-bundle/
  index.md
  concepts/<slug>.md
  queries/<slug>.md
  <foreign/path>.md
  references/<source-file>.md
  log.md
```

Native llmwiki pages export under `concepts/<slug>.md` or `queries/<slug>.md`. Imported foreign pages re-export to their original bundle-relative `.md` path when that path is safe, URL-safe, non-reserved, and uncontested. If the original path is unsafe or collides, llmwiki falls back to the slug path and returns a warning.

Each page document includes OKF standard frontmatter plus an `x-llmwiki` block with compiler metadata:

```yaml
type: concept
title: Retrieval-Augmented Generation
description: Combining retrieval with generation to ground answers.
tags:
  - rag
x-llmwiki:
  schemaVersion: "0.1"
  pageDirectory: concepts
  contentHash: "..."
  sources:
    - rag-notes.md
  freshnessStatus: fresh
```

`type` is the page's `kind` when it declares one, `query` for pages under `wiki/queries/`, and `concept` otherwise. `timestamp` is the page's `updatedAt`, falling back to its `createdAt`; a page that declares neither exports no `timestamp` at all, so the bundle never records a time the page did not have.

The body is markdown. llmwiki rewrites `[[wikilinks]]` to OKF-style links and appends a human-readable `# Citations` section. Structured citation data also lives under `x-llmwiki.citations`.

## Importing is a trusted operation

```ts
const written = await wiki.importOkf("./dist/knowledge-bundle", { trusted: true });
```

Importing used to be review-gated by default: an untrusted import staged every document as a review candidate under `.llmwiki/candidates/`. Staging is **retired**, because no surface promotes a candidate into the wiki — there is no approve command, no SDK method and no MCP tool — so a staged document could never become a page.

An import that does not name `trusted: true` therefore **refuses** with a typed error rather than staging. That leaves `dryRun` for inspection and `trusted: true` for the real write, both covered below.

Candidate files written by an earlier version are still readable: the viewer's review list and `wiki_status`'s `pendingCandidates` count keep listing `.llmwiki/candidates/*.json`, and nothing deletes them. They simply have no producer and no consumer left.

## Preview before importing

```ts
const preview = await wiki.importOkf("./dist/knowledge-bundle", { dryRun: true });
```

Dry run is useful for evaluating an unfamiliar bundle. It reports the pages that would be imported, the pages that would be skipped, and the reason for each skip. It makes no writes and calls no LLM.

## Trusted import

```ts
const written = await wiki.importOkf("./internal-bundle", { trusted: true });
```

`trusted: true` writes pages directly into `wiki/` and refreshes links and indexes. Use it only for bundles whose content and provenance you already trust. It is the only surviving import arm, and it is not reachable over MCP: the server exposes no import tool at all.

<Warning>
  OKF import reads external markdown and frontmatter. There is no review queue to catch a bad page: `trusted: true` writes straight into the wiki. Preview an unfamiliar bundle with `dryRun` first.
</Warning>

## Re-export behavior

When you import a foreign OKF bundle, llmwiki stores the original OKF frontmatter under imported provenance. On re-export:

- Foreign raw `type` values are preserved, even when they are not llmwiki page kinds.
- Foreign producer-specific keys are preserved.
- Current llmwiki standard fields (`title`, `description`, `tags`, `timestamp`) are derived from the current page, so local edits are reflected.
- `x-llmwiki` is regenerated from current llmwiki state.
- `x-okf` is not emitted; it is an internal imported-provenance record.
- Safe original nested paths are restored, so foreign bundle layouts can round-trip.
- Native `[[wikilinks]]` to imported foreign pages are exported to that page's restored OKF path.

This keeps the bundle honest: foreign metadata is not discarded, but stale standard fields are not blindly replayed after local edits.

<Note>
  Path restoration is conservative. Non-`.md`, URL-unsafe, reserved, escaping, or colliding foreign paths fall back to `concepts/<slug>.md` or `queries/<slug>.md` with a warning.
</Note>

## Programmatic and agent access

Use the SDK when your application owns the trust decision:

```ts
const bundle = await wiki.exportOkf({ out: "./dist/okf" });
const preview = await wiki.importOkf("./partner-bundle", { dryRun: true });
const written = await wiki.importOkf("./internal-bundle", { trusted: true });
```

MCP is export-only. The MCP server exposes `export_okf`, which takes a required `stackId`; it exposes no import tool, because an MCP caller could only ever stage imported documents and staging is retired. An agent that needs a bundle written into the wiki has to go through the SDK.

## OKF versus JSON export

| Use case | Recommended format |
|----------|--------------------|
| Exchange compiled knowledge with another OKF-aware tool | OKF |
| Review an external knowledge bundle before merging it into your wiki | OKF import |
| Feed the Atomic Memory bridge | JSON export with a `projectId` |
| Load a graph or table-oriented downstream pipeline | JSON / JSON-LD / GraphML |
| Share a human-readable portable bundle | OKF |

See the [SDK guide](/guides/sdk) for the export and import methods.
